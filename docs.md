# Архитектура и границы проверки

## План

1. Найти документированные API и изучить проекты, отделить утверждения об игре от сторонних скриптов.
2. Построить независимый симулятор: ограниченный JSON → нормализация → подсчёт → детерминированный план → адаптер с управлением состояниями.
3. Проверить ядро unit-тестами, интерфейс — в браузере. Не переносить результаты на чужую игру.
4. Публикация и проверка состава файлов.

## Модули

- `schema.js` и `loader.js`: независимая валидация, ограничения и изолируемая HTTP-загрузка; URL allowlist, без редиректов и credentials.
- `inventory.js`, `planner.js`: расчёт и сортировка; план не мутирует исходный массив.
- `builder.js`: `idle → running ↔ paused → completed / cancelling → cancelled / failed`; после начала шага он не прерывается. Пока шаг отменяется, параллельный старт запрещён.
- `adapters.js`: только mock имеет эффекты; реальные игровые и экономические методы отказывают. `roblox/Adapters.luau` — контракт отдельно от браузерного кода.
- `main.js`, `preview.js`, `logger.js`: UI, проекция, журнал. Значения вводятся пользователем, не получают данные из Roblox.

## Что не проверено

Интеграция с BABFT, серверная поддержка координат/размеров/поворотов/цветов, наличие и соответствие игровых предметов, загрузка через Roblox HttpService, UI в Roblox, реальная игровая экономика. Приложение не пытается соединяться с Roblox. Браузерная загрузка зависит от сети и CORS. Проекция — не трёхмерный симулятор, не учитывает оси поворота X/Z и не проверяет пересечения.
